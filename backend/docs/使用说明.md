# 使用说明

线虫摆动频率分析系统：上传线虫视频，自动识别、跟踪并统计每只线虫的头部摆动次数与频率。
更简短的三步上手见包根目录 `README.md`；算法原理与开发细节见 `技术说明.md`。

## 1. 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（64 位） |
| Python | 3.10 ~ 3.12 |
| 显卡 | 不需要；有 NVIDIA 显卡可开启 GPU 加速（见 7.2） |
| Node.js | 不需要（界面已构建在 `backend/static`，由后端托管） |
| 网络 | 仅首次安装依赖需要（约 400 MB） |
| 磁盘 | 建议预留 2 GB 以上 |

## 2. 快速开始

1. 安装 Python 3.10 以上版本，安装时勾选 `Add python.exe to PATH`
2. 双击 `1-安装依赖.bat`，等待 5~15 分钟（自动创建 `.venv` 并安装 CPU 版 PyTorch）
3. 双击 `2-启动.bat`，约 10~30 秒后浏览器自动打开 <http://127.0.0.1:5000>

以后再使用，只需要第 3 步。停止服务：关闭那个命令行窗口。

| 脚本 | 用途 |
| --- | --- |
| `1-安装依赖.bat` | 首次安装依赖（CPU 版，日常使用够） |
| `2-启动.bat` | 启动服务并自动打开浏览器 |
| `3-开发模式-启动前端.bat` | 可选，需要 Node.js，改界面时才用 |
| `4-安装GPU训练依赖.bat` | 可选，安装 CUDA 版 PyTorch（GPU 推理 / 训练） |
| `5-训练模型.bat` | 可选，用自己的数据训练模型 |

## 3. 界面怎么用

1. 左侧上传线虫视频（mp4 / avi / mov），点开始处理；
2. 右侧实时显示标注画面，每个编号显示：摆动次数（C 形/S 形各计 1 次）、完整周期数、实时/平均频率、运动类型；
3. 处理完成后下载：结果视频、子视频压缩包、摆动汇总 CSV、汇总 JSON。

## 4. 结果文件在哪

- 上传的原始视频：`backend\data\uploads\`
- 处理结果：`backend\data\results\`（任务号格式 `yyyymmdd_hhmmss_随机6位`）

| 后缀 | 说明 |
| --- | --- |
| `_result_<任务号>.mp4` | 标注后的结果视频 |
| `_id_pose_summary.json` | 每只虫的汇总（摆动次数、频率、运动类型、活性） |
| `_swing_summary.csv` | 摆动汇总表，Excel 可直接打开 |
| `_log.json` | 逐帧统计 |
| `_sub_videos.zip` | 该任务全部子视频压缩包 |
| `sub_videos/<任务号>/worm_<ID>_cycles_<次数>.mp4` | 单只虫的裁剪子视频 |

## 5. 常见问题排查

| 现象 | 处理 |
| --- | --- |
| 提示找不到 Python | 重装 Python 并勾选 `Add python.exe to PATH`，或重启电脑 |
| pip 下载慢 / 超时 | `pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 报缺少 VCRUNTIME140.dll 或 torch 导入失败 | 安装 <https://aka.ms/vs/17/release/vc_redist.x64.exe> |
| 5000 端口被占用 | 启动前 `set PORT=5001`，改用 <http://127.0.0.1:5001> |
| 提示模型文件不存在 | 确认 `backend\models\best.pt` 存在（约 60 MB） |
| 页面打不开 | 首次启动要加载模型，等 10~30 秒后刷新；`/health` 可看状态 |
| 处理很慢 | 见 7.1 提速开关 |
| 大视频卡顿 | 分辨率越高越慢，建议先用 30 秒以内片段试跑，或先压缩视频 |

## 7. 参数与调优

### 7.1 识别与跟踪调优（默认已优化）

针对三类现象分别做了处理：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 虫子数量偏多 | NMS 抑制太弱导致同一只虫出现多个框；低分误检也进入统计 | 候选阈值 `INFER_CONF` **0.25**、`MIN_CONFIDENCE` **0.3**；去重改为**掩码优先**（`DEDUP_MASK_IOU=0.3`），不再仅凭框 |
| 瞬时误检冒出来又消失 | 只要匹配成功就立即显示 | 新目标需**连续命中 5 帧**才确认显示；未确认的瞬时误检也**不再产生子视频文件** |
| 静止后漏检、再出现换新序号 | 轨迹 60 秒后被回收；静止目标活性为 0 被过滤 | ID 保留延长到 **600 秒**；**已确认目标即使静止也继续显示**（不会被活性阈值过滤） |
| **同一只虫出现两个 ID** | 模型对同一只虫给出两个掩码（框 IoU 低、掩码 IoU 高），旧 NMS 只看框拦不住；或残留框叠在实时框上 | 掩码优先去重 + 出生门控（同一只虫不重复建 ID）+ 残留框压在实时框上时不再绘制 |
| **两条贴合的虫只剩一条 ID** | 旧去重只看框，两条贴合的虫框重叠会被误删一条；模型只给一条检测时另一条被判丢失 | 去重不再仅凭框；**贴合共享**：两条 ID 都保活（共享期间两条都暂停摆动计数）；残留框不再叠加迷惑 |
| 贴合期间摆动次数短暂不涨 | 两虫共用一条检测，关键点不可信，按设计暂停计数 | 正常现象，两虫分开后自动恢复计数 |
| 慢速小幅摆动没被计入 | 体态幅度门槛是体长的 10% | 降低 `SWING_POSTURE_MIN_AMP_PCT`（10 → 8） |
| 觉得把"过渡姿势"也算了一次 | 默认 `each`：C 和 S 都算独立姿态 | 改用 `SWING_POSTURE_UNIT=pair`（只有弯曲方向翻转才计） |
| 想恢复旧的计数口径 | — | 启动前 `set SWING_POSTURE_MODE=0` |

关键参数（`backend/worm_processing.py` 顶部，均可按需修改）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `INFER_IMGSZ` | 960 | 推理分辨率，越大越不容易漏检、越慢 |
| `INFER_CONF` | 0.25 | 送入跟踪器的候选阈值；调低更灵敏但误检变多 |
| `MIN_CONFIDENCE` | 0.3 | 检测置信度下限 |
| `overlap_threshold` | 0.3 | NMS 重叠阈值；调大容易出现同一只虫多个框 |
| 确认帧数 `confirm_hits` | 5 | 新目标需连续命中多少帧才显示 |
| `TRACK_PERSISTENCE_SEC` | 600 | 丢失后 ID 保留时长（静止漏检后仍能接回原序号） |
| `GHOST_OVERLAY_SEC` | 5 | 残留框继续显示的时长（框停在最后位置，不再按速度外推）；**只在结果视频里画（实线框），实时预览不画** |
| `cost_threshold` | 2.5 | 关联成本上限，越大越容易接回原 ID |

重叠/贴合相关（新）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `DEDUP_MASK_IOU` | 0.3 | 掩码 IoU 超过该值判为**同一只虫**（重复识别去重）。调小＝去重更狠；注意别调到低于两条虫的正常掩码重叠 |
| `SHARED_IOU` | 0.25 | **贴合共享**：预测框与在跟踪框重叠超过该值，判为"两条虫贴合、被一条检测覆盖"，两条 ID 都保活 |
| `BIRTH_BLOCK_MASK_IOU` | 0.3 | 新检测与已匹配检测掩码重叠超过该值 → 不新建 ID（同一只虫） |
| `BIRTH_FRAGMENT_CONTAIN` / `BIRTH_FRAGMENT_AREA` | 0.8 / 0.4 | 框被已有框包住且面积很小 → 判为片段，不新建 ID |
| `BIRTH_COOLDOWN_FRAMES` / `BIRTH_COOLDOWN_OVERLAP` | 12 / 0.5 | 同一位置 12 帧内掩码明显重叠 → 不重复新建 ID |
| `GHOST_SUPPRESS_IOU` | 0.25 | 残留框压在实时框上时**不再绘制**（ID 与表格数据仍保留） |

以上都可用环境变量临时覆盖，例如 `set DEDUP_MASK_IOU=0.35`。

画面上的残留框按输出分开处理（`backend/app.py` 顶部 `PREVIEW_OVERLAY_MODE` / `RESULT_OVERLAY_MODE`）：

| 输出 | 叠加模式 | 效果 |
| --- | --- | --- |
| 网页“实时处理区”的实时画面 | `debug` | 残留目标（识别短暂中断的目标）完全不显示，画面里只出现真实检测 |
| 处理完成后下载的结果视频 | `release` | 残留目标与真实检测一样画**实线框**，并带“残留 丢Nf”标签 |

可用环境变量临时覆盖（启动前执行，不改代码）：

```bat
set INFER_IMGSZ=640        & rem 提速，允许更多漏检
set INFER_CONF=0.2         & rem 更灵敏，误检会变多
set MIN_CONFIDENCE=0.25    & rem 同上
set DEVICE=cpu             & rem 强制 CPU
```

### 7.2 GPU 加速

装了 CUDA 版 PyTorch（双击 `4-安装GPU训练依赖.bat`，cu128 适配 RTX 50 系）后，推理自动使用 GPU，
启动日志会打印 `[信息] 推理设备: GPU ...`；访问 `/health` 可查看 `device` 与 `infer_imgsz`。

- 强制用 CPU：启动前 `set DEVICE=cpu`
- GPU 下 `INFER_IMGSZ=960` 的速度代价基本可忽略（预计 20 FPS 以上），不必再降到 640
- 显存占用：imgsz 960 约 1~2 GB

### 7.3 摆动计数参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
摆动计数默认按「**体态**」计：身体形成一次 **C 形或 S 形**算 1 次，幅度按**体长百分比**衡量，
**微小摆动不计入**（同一个 C 形里的头颈抖动不会被重复计数）。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `SWING_POSTURE_MODE` | 1 | 1=按体态（C/S 形）计数（默认）；0=退回旧的"角度极值 + 三路融合"口径 |
| `SWING_POSTURE_MIN_AMP_PCT` | 10.0 | **有效弯曲的幅度门槛（体长 %）**：低于此值不算一次摆动 |
| `SWING_POSTURE_RELEASE_PCT` | 5.0 | 迟滞释放线：幅度回落到该值以下才算这个姿态结束；结束后再出现同样姿态算新的一次 |
| `SWING_POSTURE_HOLD_FRAMES` | 2 | 同一体态需连续保持多少个**新观测**才计入（排除单帧抖动） |
| `SWING_POSTURE_MIN_LOBE_PCT` | 6.0 | 判 S 形时两个弯各自的幅度下限（体长 %） |
| `SWING_POSTURE_UNIT` | `each` | `each`=每个不同的 C/S 姿态各计 1 次；`pair`=只有弯曲方向翻转才计 1 次 |
| `SWING_MIN_GAP_SEC` | 0.10 | 两次计数之间的最小时间间隔，抖动多可增到 0.15~0.2 |

以下三个只在 `SWING_POSTURE_MODE=0`（旧口径）时生效：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `SWING_COUNT_MODE` | `swing` | `swing` 单方向摆动计 1 次；`cycle` 一个完整往返计 1 次 |
| `SWING_MIN_AMP_DEG` | 3.0 | 角度信号的最小幅度（度），摆动普遍偏小可降到 1~2 |
| `SWING_BASELINE_SEC` | 2.5 | 去漂移基线窗口，摆动更慢可增大到 3~4 |
| `SWING_FUSION` | 1 | 三路信号融合（0=只用头部弯曲角单信号） |
| `TRACK_PERSISTENCE_SEC` | 60 | 丢失后 ID 保留时长 |
| `GHOST_OVERLAY_SEC` | 5 | 残留框继续绘制时长（仅在结果视频里画实线框，实时预览不画） |

### 7.4 停止运动后的统计口径（重要）

虫子短暂运动后停下并被漏检时，旧版本会把频率与活性冻结在运动时的高值。现已改为：

| 指标 | 现在的口径 |
| --- | --- |
| 平均频率 `freq` | 摆动次数 ÷ 轨迹存续时间（含丢失/未观测时间），停下后随时间自然下降 |
| 参考值 `avg_freq_observed` | 摆动次数 ÷ 有效观测时间（只算真正看到目标的帧），保留在 CSV/JSON 供对照 |
| 实时频率 `live_freq` | 按视频时间窗口（默认 3 秒）统计，事件随时间过期，停下后衰减为 0 |
| 活性 `activity_score` | 分母为窗口应有帧数（没观测到的帧按不活跃计），不再虚高 |
| 数据过期 | 超过 `STALE_UNOBSERVED_SEC`（默认 3 秒）没有新观测时，表格显示未观测时长，实时频率与活性显示 -- |
| 轨迹条目 | 已确认目标即使长时间没被检测到，也继续留在表格里，不会凭空消失 |

### 7.5 ROI 找回（针对静止后长期漏检）

对已确认但连续多帧没匹配上的轨迹，在它最后位置的 ROI 内用低阈值再做一次小图推理找回，命中后并入原轨迹，不换序号。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `ROI_RECOVER` | 1（开启） | 设为 0 关闭找回 |
| `ROI_RECOVER_CONF` | 0.15 | 找回用的低置信度阈值 |
| `ROI_RECOVER_INTERVAL` | 3 | 每 N 帧做一次找回（控制耗时） |
| `ROI_RECOVER_IMGSZ` | 320 | 找回推理分辨率 |
| `STALE_UNOBSERVED_SEC` | 3.0 | 多久没观测就算数据过期 |

### 7.6 摆动与活性的四项修正（A1 / A2 / B1 / B2）

- **A1 阈值下限自适应**：下限从固定 8 度改为 max(3 度, 0.25×近期幅度)，小幅度摆动不再被丢掉；
  噪声保护提高到 3.5×高频噪声，抑制抖动误计。
- **A2 三路信号融合**：同时用 头部弯曲角 + 中点横向偏移 + 身体弯曲角，同一时间窗（`SWING_FUSE_WINDOW`，默认 0.3 秒）
  内至少两路检测到极值才算一次摆动。实测某只头部摆幅小的虫：单路 3 次，融合后 6 次（找回漏计）；
  三路一致的虫计数不变。可用 `SWING_FUSION=0` 退回单信号。
- **B1 运动活性分母修正**：分母改为窗口内应有样本数（帧率×窗口÷关键点间隔），
  修正了之前活性上限只有 0.5 的问题。
- **B2 两个活性分开显示**：界面与 CSV 分别给出 摆动活性（平均摆动频率÷5）与
  运动活性（非静止样本占比），不再共用同一个名字。

相关环境变量：`SWING_MIN_AMP`（绝对下限，默认 3.0）、`SWING_MIN_AMP_RATIO`（默认 0.25）、
`SWING_FUSION`（默认 1）、`SWING_FUSE_WINDOW`（默认 0.3）。

### 7.7 诊断模式（排查计数不准）

启动前执行 `set SWING_DIAG=1` 再启动服务，处理完一个视频后会在 `backend\data\results\` 里额外生成：

| 文件 | 内容 |
| --- | --- |
| `<任务号>_swing_diag.csv` | 每只虫**逐帧**的三路信号值（bend / mid / curv）以及各路与融合事件标记 |
| `<任务号>_swing_diag_track<ID>.png` | 每只虫一张曲线图：三条信号曲线 + 各路事件竖线 + 融合事件黑点 |

网页左侧下载区会多出「下载摆动诊断CSV」按钮（只在诊断模式生成文件时显示）。

怎么用这张图判断问题：

| 图上现象 | 含义 | 对应调整 |
| --- | --- | --- |
| 曲线有明显周期，但某一路的事件竖线缺失 | 该路信号幅度达不到阈值（漏计） | 降低 `SWING_MIN_AMP_RATIO`（0.25→0.15） |
| 事件竖线比曲线波峰还多 | 该路把抖动当摆动（误计） | 提高噪声保护或收紧 `SWING_FUSE_WINDOW` |
| 三路都有事件，但黑点（融合）明显少 | 融合窗口太小，事件时间没对齐 | 把 `SWING_FUSE_WINDOW` 从 0.3 调到 0.4~0.5 |
| 曲线平稳却出现黑点 | 误计，需要提高阈值下限 | 提高 `SWING_MIN_AMP`（3.0→5.0） |

诊断模式会增加内存占用与少量导出耗时（多写 CSV/PNG），平时保持默认关闭（0）。
