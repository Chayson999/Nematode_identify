## 1. 摆动计数与频率口径

**信号**：默认取头部相对体轴的弯曲角（`SWING_SIGNAL='bend'`，用 kp0->kp2 与 kp0->kp[-1] 的夹角），
整体平移与转向会被抵消；可切回绝对头部方向角（`absolute`）。

**预处理与判定**（`SwingCounter`）：

1. 角度 unwrap 连续化，避免 ±180 度缠绕产生假过零；
2. 滚动中位数基线（`SWING_BASELINE_SEC=2.5` 秒）扣除整体漂移，得到残差 r(t)；
3. 轻量 EMA 平滑，抑制关键点抖动；
4. 自适应阈值 `A = clip(0.45 * p90(|r|), SWING_MIN_AMP_DEG, SWING_MAX_AMP_DEG)`；
5. 极值反转检测：残差从最近极值回撤超过 A 才确认一个极值（峰/谷），避免同一摆动重复计数。

**计数口径**（默认已改为按体态计数，见下一节）：

- `SWING_POSTURE_MODE=1`（默认）：**一次 C 形或 S 形 = 1 次**，幅度用体长百分比衡量，微小摆动不计入；
- `SWING_POSTURE_MODE=0` 退回旧口径：
  - `SWING_COUNT_MODE='swing'`：每个极值 = 头部单方向摆动 1 次，一次左右往返 = 2 次；
  - `SWING_COUNT_MODE='cycle'`：只对峰计数，一次左右往返 = 1 次完整周期。

**频率**：

- 平均频率 = 摆动次数 / 有效观测秒数（丢失期间不计时）；
- 实时频率 = 最近 `SWING_LIVE_WINDOW_SEC` 窗口内事件数 / 窗口秒数，且至少累计 1 秒才输出，避免开头虚高；
- 瞬时频率 `inst_freq` = 最近若干事件间隔中位数的倒数；
- 统计只喂入**真实提取**的关键点（每 3 帧刷新一次，中间帧沿用上一次），剔除预测外推点造成的假摆动。

**历史缺陷（已修复）**：`TrackHistory.get_dominant_motion_type` 曾对 deque 切片，
累计 30 个运动样本（约 3 秒）后每帧抛 TypeError，导致识别中断、表格清空。现改为先转 list，并有回归测试。

### 1.5 体态计数：一次 C 形 / S 形 = 1 次（默认口径）

旧口径数的是**头部弯曲角信号的极值**，它会把"身体保持同一个 C 形、头颈小幅抖动"反复计成多次摆动。
实测（3 个视频各 300 帧，逐帧用 11 点中心线回算真实体态）：

| 现象 | 实测数据 |
| --- | --- |
| 相邻两次计数的弯曲方向**相同**（同一姿态被重复计数） | 2day-2 ID6 **7/7**、ID4 **6/6**；2day-1 ID3 **5/5**；Swim-1 ID6 5/6 |
| 幅度尺度差异极大 | 各轨迹事件幅度中位数从 **6.1%** 到 **85.4% 体长** → 用"角度"做阈值不可能通用 |
| 幅度 <5% 体长的"微小摆动"被计入 | Swim-1 3/71、2day-2 1/41 |

新口径（`PostureSwingCounter`）：

1. **体态指标**（尺度无关，单位体长 %）：取体长 25%/50%/75% 三点相对头尾连线的横向偏移
   `s25/s50/s75`；幅度 `A = max(|s25|,|s50|,|s75|)`；
   形状 = `C`（三点同号）/ `S`（首尾异号且两弯都够大、中段接近直线）/ `mixed`（不明确）；
   方向 = 主弯曲侧符号。
2. **幅度门** `SWING_POSTURE_MIN_AMP_PCT`（默认 **10% 体长**）：`A` 低于门限 → 不算摆动；
3. **持续门** `SWING_POSTURE_HOLD_FRAMES`（默认 2）：同一体态需连续 2 个**新观测**；
   关键点每 `KEYPOINT_UPDATE_INTERVAL` 帧才更新，同一份观测重复喂入**不累计**持续时间
   （否则单次观测就能满足条件）；
4. **迟滞门** `SWING_POSTURE_RELEASE_PCT`（默认 5% 体长）：幅度回落到该值以下才算姿态结束，
   结束之后再出现同样姿态算新的一次 —— 同一个 C 形里的抖动不会被重复计数；
5. **单位** `SWING_POSTURE_UNIT`：
   - `each`（默认）：**每个不同的体态（C / S 或方向变化）各计 1 次**；
   - `pair`：只有弯曲方向翻转才计 1 次（同一方向的 C/S 视为同一次）；
6. **间隔门** `SWING_MIN_GAP_SEC`（默认 0.1 s）；
7. 姿态不明确（`mixed`）不计入，也不触发释放。

计数维护：`swing_count`/`cycles`/`posture_count` = 体态次数；`cycle_count` = 完整往返次数
（相邻已计数体态的方向翻转折算 `(flips+1)//2`）；`count_mode='cycle'` 时实时/瞬时频率按方向翻转统计。
`cycle_counts` 另附 `posture_shape` / `posture_amp_pct` / `count_unit` 便于核对
（前两个是**最近一帧**的体态读数，不是"计数时刻"的读数），并透传到 `track_data` 供前端/CSV 使用。

实测对比（同一批 300 帧，imgsz=960，RTX 5060，模式切换只需 `SWING_POSTURE_MODE`）：

| 视频 | 每条轨迹计数（旧 → 新） | 说明 |
| --- | --- | --- |
| 2day-1 | ID1 7→4，ID3 6→2，ID4 8→6 | 把同一姿态的重复计数压掉 |
| Swim-1 | ID2 19→25，ID8 18→19，ID5 6→15 | 快虫：旧口径因融合条件漏计，新口径按体态如实计数（≈1.3 个往返/秒） |
| 2day-2 | ID4 7→1，ID6 8→1 | 慢虫：原来 6~7 次方向相同的"假摆动"被去掉 |

被计数帧的逐帧拼图（中心线 + 25/50/75% 采样点 + 体态标签）见验证脚本输出，
人工核对结果：每次计数都对应一个肉眼可见的 C 形或 S 形，方向严格交替，幅度均 ≥ 门限。

## 2. 视觉残留：识别中断保留序号

| 机制 | 参数 | 说明 |
| --- | --- | --- |
| ID 保留 | `TRACK_PERSISTENCE_SEC=600` | 丢失后轨迹保留 600 秒，不被回收、不被新目标抢占；next_id 只增不减，回收的 ID 不复用；已确认目标即使静止也继续显示 |
| 残留绘制 | `GHOST_OVERLAY_SEC=5` | 丢失后残留框停在最后一次真实检测的位置，并继续写该目标子视频；**实时预览不绘制残留框，结果视频里残留框画实线** |
| 叠加模式 | `OVERLAY_MODE_DEBUG` / `OVERLAY_MODE_RELEASE` | 实时预览=debug（残留目标不上屏）、结果视频=release（残留目标画实线框）；两路共用同一次推理与跟踪 |
| 搜索半径 | `_match_gate()` | 丢失越久搜索半径越大（上限受 `GHOST_REID_MAX_LOST` 约束） |
| 找回匹配 | 第三阶段 | 位置 + 尺寸 + 外观加权，丢失 ≥1 帧、成本 <1.0 即接回原 ID；不叠加低 IoU 惩罚 |
| 预测次数 | 每帧一次 | 旧实现丢失轨迹会 predict 两次，残留框漂移更快，已修正 |

注意：残留期间不把预测关键点送入摆动计数，因此频率不会被稀释。

## 2.5 重复识别抑制与贴合处理（线虫重叠 / 贴合场景）

线虫重叠或贴合时会同时出现两种相反的失效，两类都要治：

| 失效模式 | 现场证据（同一批 150 帧实测） | 处理 |
| --- | --- | --- |
| 同一只虫被重复识别 | 模型对同一只虫给出"整只 + 局部片段"两个掩码：**框 IoU 只有 0.22~0.25**（旧 NMS 阈值 0.3 拦不住），但**掩码 IoU 0.37~0.50**；Swim-1 里 5 帧 | `apply_nms` 改为**掩码优先去重**：掩码 IoU > `DEDUP_MASK_IOU`(0.3) 判为同一只虫；框几乎完全重合且掩码有交集也判同一只虫 |
| 两条贴合/交叉的虫被并成一条 | 旧实现**只看框**：Swim-1 的 45 次抑制里有 **4 次是两条不同的虫**（掩码 IoU 0.04~0.10、框 IoU 0.30~0.38）被当重复删掉；模型只给一条检测时，另一条变残留、5 秒后从画面消失 | ① 去重不再仅凭框；② 出生门控；③ **贴合共享**：见下 |

贴合共享（`_resolve_shared_detections` / `_apply_shared_tracks`）：

- 条件：轨迹已确认、上一帧还在（`lost_frames <= SHARED_MAX_LOST_FRAMES`），
  且它的预测框与某条**已匹配检测**的框重叠 ≥ `SHARED_IOU`(0.25)；
- 处理：判为"两条虫贴在一起、被一条检测覆盖"。该轨迹**保持存活**——不进入视觉残留、
  不丢 ID、框停在原地、继续写子视频、继续出现在画面与表格里（`is_shared`）；
- 两条虫分开后自动回到各自独立检测；
- 共享期间**两条虫都暂停摆动计数**：两虫共用一条检测，关键点与幅度都不可信，
  照常计数会让两条虫算出趋同甚至重复的频率。

出生门控（`_should_block_birth`）三道闸，防止同一只虫被重复建 ID：

1. 与某条已匹配检测的掩码重叠 > `BIRTH_BLOCK_MASK_IOU`(0.3) → 同一只虫的重复检测，不新建；
2. 框被在跟踪目标的框包住 ≥ `BIRTH_FRAGMENT_CONTAIN`(0.8) 且面积 < `BIRTH_FRAGMENT_AREA`(0.4)倍 → 片段，不新建；
3. 出生冷却：同一位置 `BIRTH_COOLDOWN_FRAMES`(12) 帧内、掩码重叠 > `BIRTH_COOLDOWN_OVERLAP`(0.5) → 不新建。
   冷却**只看掩码**：两条贴在一起的虫"框"本来就重叠（实测 0.2~0.7），按框判会把另一条虫挡掉，
   那就又变成"两条虫合成一条"了。

配套改动：

- **子视频只在确认后创建**（`confirm_hits=5`）：未确认的瞬时误检不再留下垃圾 `worm_N.mp4`
  （线上日志里出现过"分配 18 个 ID、其中 4 个从未出现"的情况）；
- **残留框压在实时框上时不再绘制**（`GHOST_SUPPRESS_IOU`(0.25)，标记 `shadowed`）：
  ID 与表格数据保留，只是不在画面上叠第二个框，避免"看起来重复识别"；
- 去重后**掩码按新顺序重取**（`masks = detections.mask`）：旧实现去重后仍用旧下标索引掩码，
  一旦删掉检测，后面的框会配上别的虫的掩码，直接影响中心线 / 姿态 / 摆动计数。

实测对比（同一批 150 帧、`INFER_IMGSZ=960`、RTX 5060）：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| Swim-1「误删另一条虫」 | 4 次 | **0 次** |
| Swim-1 残留框压实时框 | 122 次 | **51 次** |
| Swim-1 贴合共享（两条都保活） | 无此机制 | **117 帧** |
| 2day-2_1 残留框压实时框 | 23 次 | 22 次 |
| 2day-2_1 残留框被压住不绘制 | 无此机制 | 21 帧 |
| 同帧框重叠 >0.3 的 ID 对里「掩码重叠（真重复）」 | — | **0 帧** |

## 3. 跟踪关联改进与指标

关联成本（`associate_detections_to_tracks`）权重：

| 项 | 权重 | 说明 |
| --- | --- | --- |
| IoU 成本 | 0.25 | 预测框与检测框重叠度 |
| 运动一致性 | 0.45 | 卡尔曼预测位置误差 + 目标尺寸稳定性 |
| 方向一致性 | 0.15 | 运动方向与位移方向一致性 |
| 外观特征 | 0.15 | 区域 Hu 矩等 11 维特征距离 |

其他机制：

- 活性评分：运动类型窗口占比，并增加已累计到摆动的通道，原地摆动的线虫不会被活性阈值过滤；
- 低活性目标不绘制轨迹、不进入前端统计，但仍可被跟踪；
- 历史改进报告口径的指标：ID 闪烁 <2%、跟踪丢失 <3%、误检过滤 >99%；
- 本次针对丢帧的实测（300 帧、5 只虫）：轨迹丢失事件 24 → 3，ID 切换 0（详见 `使用说明.md` 7.1）。

## 4. 模型训练（GPU）

前提：NVIDIA 显卡 + 较新驱动；运行 `4-安装GPU训练依赖.bat` 安装 CUDA 版 PyTorch（cu128，适配 RTX 50 系）。

数据集为 YOLO 格式：

```
D:\data\worm\
├─ images\train\  images\val\      (jpg/png)
├─ labels\train\  labels\val\      (同名 txt：类别 中心x 中心y 宽 高，均 0~1)
└─ data.yaml                        (path / train / val / nc / names)
```

训练：

```powershell
cd backend
.venv\Scripts\python.exe tools\train_yolo.py --data D:\data\worm\data.yaml --epochs 100 --imgsz 960 --batch 8
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--model` | `yolov8n.pt` | 初始权重，首次自动下载 |
| `--epochs` | 100 | 数据少可 150~300 |
| `--imgsz` / `--batch` | 960 / 8 | 显存不足降到 640 / 4 |
| `--device` | 0 | GPU 编号；cpu 表示不用显卡 |

训练输出在 `backend/runs/train/worm/`，`weights/best.pt` 会复制到 `backend/models/best.pt`
（原文件备份为 `best.pt.bak`），重启服务生效。建议至少 200~500 张标注图。

## 5. 代码结构与数据流

### 5.1 模块

| 文件 | 职责 |
| --- | --- |
| `backend/app.py` | Flask 服务：路由（`/upload`、`/health`、`/task/<id>/status`、`/media/<file>`、`/download/<file>`、`/sub_video/...`）、任务线程、WebSocket 逐帧推流、结果汇总（JSON/CSV）、前端静态托管（`serve_frontend`）、`HOST`/`PORT` 环境变量 |
| `backend/worm_processing.py` | 算法核心：配置常量、`init_model`、`EnhancedWormTracker`、`KalmanBoxTracker`、`SwingCounter`、`TrackHistory`、`process_frame`、`_draw_contour_overlay` |
| `backend/tools/train_yolo.py` | GPU 训练脚本（训练完自动安装 best.pt） |
| `backend/tests/` | 单元测试（20 个用例） |
| `frontend-src/` | 前端源码（CRA）；构建产物由后端托管 |

### 5.2 单帧数据流

```
读取帧
  -> YOLO 推理（imgsz=INFER_IMGSZ, conf=INFER_CONF, device）
  -> supervision.Detections
  -> 置信度 / 最小面积过滤 -> NMS（overlap_threshold 0.5）
  -> 关联匹配（IoU 0.25 + 运动一致性 0.45 + 方向 0.15 + 外观 0.15，匈牙利算法）
  -> 卡尔曼更新；未匹配轨迹进入丢失处理
  -> 关键点提取（每 KEYPOINT_UPDATE_INTERVAL=3 帧一次，窗口内骨架化 + 11 点等距采样）
  -> 摆动计数（SwingCounter，只用真实关键点）
  -> 残留（ghost）预测与找回匹配
  -> 绘制标注（_draw_contour_overlay：轮廓 + 框 + 计数/频率标签）
  -> WebSocket 推送 / 子视频写入 / 结果落盘
```

### 5.3 主要类

| 类 | 作用 |
| --- | --- |
| `EnhancedWormTracker` | 跟踪器主体：关联、丢失与残留处理、找回匹配、子视频写入、统计同步 |
| `KalmanBoxTracker` | 单目标卡尔曼状态 `[cx, cy, w, h, vx, vy, vw, vh]`，提供预测框/速度/关键点外推 |
| `TrackHistory` | 单目标历史：中心线、头角、速度、曲率、运动类型、活性评分 |
| `SwingCounter` | 摆动事件检测与频率统计（swing / cycle 两种口径） |
| `MotionClassifier` | 运动类型分类：静止 / 前进 / 后退 / 正弦摆动 / 转身 |

### 5.4 性能相关

- 关键点提取降至每 3 帧一次，且只在目标裁剪窗口内骨架化（避免全图计算）；
- 残留目标复用同一份空掩码，不再每帧每目标分配整幅布尔数组；
- 已移除与 `_draw_contour_overlay` 重复的 supervision 标注器调用；
- GPU 下启用 `torch.backends.cudnn.benchmark`；
- `/health` 返回 `device` 与 `infer_imgsz`，便于确认运行配置。

### 5.5 画面标注与残留框

两种叠加模式（`worm_processing.OVERLAY_MODE_*`，由 `app.py` 分别用于两路输出）：

| 模式 | 用在哪 | 残留目标（ghost）怎么画 |
| --- | --- | --- |
| `debug` | 网页“实时处理区”的逐帧实时画面 | **完全不上屏**：不画框、不画“残留 丢Nf”标签、不画轨迹残留点，画面里只出现真实检测 |
| `release` | 处理完成后下载的结果主视频 | 与真实检测一样画**实线框**（白色 + 深色描边双层实线），并保留“残留 丢Nf”标签 |

两路共用同一次推理与跟踪结果（`process_frame_variants`），同一帧只推理一次；
`_draw_contour_overlay(..., overlay_mode=...)` 的 `debug` 分支跳过残留目标，
`release` 分支统一走实线矩形，原先的虚线矩形绘制已移除。
子视频写的是原始 ROI 裁剪，不含任何标注，不受模式影响。

标注（清晰、非彩色）：

- 框、轮廓、标签统一使用**白色 + 深色描边**（`_MARK_COLOR` / `_MARK_OUTLINE`），不用彩色，
  避免与画面内容抢色，同时在亮背景上也看得清；
- 标签由 `_draw_label_box` 绘制：深色半透明底 + 白色加粗抗锯齿文字（字号 0.7）；
- 标签优先贴在框正上方并用同色引线连接；上方空间不足时贴框内顶部，保证序号与目标紧密对应；
- 每只虫的补充信息（次/分钟、运动类型、活性）放在框下方小号标签，左上角帧信息同样带底显示。

残留框（ghost）停在原地：

- 目标丢失后立即调用 `KalmanBoxTracker.freeze()`：把卡尔曼速度项与运动向量清零；
- 因此残留框、裁剪窗、轨迹点都停在最后一次真实检测的位置，**不再按速度外推漂移**
  （识别中断多是线虫停滞原地或短暂遮挡，按速度外推会让框越飘越远）；
- 目标重新出现后，卡尔曼由新检测重新收敛，恢复正常跟踪；ID 保留 600 秒，优先接回原序号。
